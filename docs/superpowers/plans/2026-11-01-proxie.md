# Proxie Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `proxie` + `proxie_dio` to pub.dev: an in-app Flutter HTTP inspector with breakpoints, Map Local, cURL copy, filtering, persistent history and a fast schema-aware JSON editor.

**Architecture:** A client-agnostic core engine receives canonical `ProxieRequest`/`ProxieResponse` objects from capture adapters (dart:io `HttpOverrides`, `package:http`, Dio) and returns decisions (proceed / mock / abort), pausing on breakpoints. A long-lived worker isolate owns SQLite storage and all JSON work; the UI asks it for small windows of data. The UI is a floating bubble + full-screen adaptive inspector drawn in Proxie's own overlay, with pluggable navigation adapters.

**Tech Stack:** Flutter 3.47 / Dart 3.13, pub workspaces, `sqlite3` 3.8 (FTS5), `http` 1.6, `dio` 5.11, `path_provider` 2.1, `flutter_test`, `integration_test`, Playwright (Node 24) for the web example.

**Spec:** `docs/superpowers/specs/2026-11-01-proxie-design.md`

## Global Constraints

- SDK: `environment: sdk: ^3.10.0`, `flutter: ">=3.38.0"` (floor set by `sqlite3` 3.8 / `path_provider` 2.1).
- `proxie` deps only: `sqlite3: ^3.8.0`, `http: ^1.6.0`, `path_provider: ^2.1.6`, `flutter`. `proxie_dio` adds only `dio: ^5.11.0` and `proxie`. No codegen for users.
- Package names: `proxie`, `proxie_dio`. License MIT. Repo `https://github.com/Omerguler/proxie`.
- Enablement: `const bool kProxieEnabled = kDebugMode || bool.fromEnvironment('PROXIE');` Every public entry point short-circuits on it so release builds without `--dart-define=PROXIE=true` tree-shake Proxie out.
- Defaults: spill-to-file threshold 256 KB; render cap 5 MB; capture tee cap 5 MB; raw-text editable below 1 MB; retention 5,000 calls / 7 days; breakpoint timeout 60 s; split-view width 700 dp.
- Default mask list — headers: `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization`; JSON keys: `password`, `token`, `access_token`, `refresh_token`, `secret` (case-insensitive). Mask string: `••••••`. Masking applies to stored/displayed copies only, never to live traffic.
- Proxie never reads or changes the host app's theme or navigation stack (overlay mode default).
- Heavy work (SQLite, JSON parse/flatten/schema/search/serialize) runs in the worker isolate on native; on web an in-process worker with the same interface.
- Lints: `flutter_lints: ^6.0.0`; `dart analyze` clean; `dart format` applied.

## Review Focus

1. **Chunked request bodies through `HttpOverrides`** — app calls `add()` several times then `close()`; expected: server receives the exact concatenated bytes, Proxie records them. (Test in Task 14.)
2. **`content-type: application/json` with invalid/non-UTF-8 body** — expected: classified as text-or-binary, raw view shows it, no exception, JSON tree shows "Invalid JSON" state. (Tests in Tasks 3 and 16.)
3. **Several calls hit breakpoints at once, or user never acts** — expected: they queue in arrival order, each times out after 60 s and continues unchanged; app never hangs. (Test in Task 8.)
4. **Proxie disabled** — expected: adapters are pure pass-through, no isolate spawned, no `proxie.db` created, `Proxie.wrap` returns child unchanged. (Test in Task 20.)
5. **Response larger than the 5 MB tee cap with no matching rule** — expected: app receives every byte intact; stored body is marked `truncated: true` and holds the first 5 MB. (Tests in Tasks 13 and 14.)
